Cliprill 0.2.2 uses a fixed self-signed certificate so app updates can retain the
same signing identity. Requires macOS 14 or later. Source is **AGPL-3.0-only**.

### What changed

- Release workflows explicitly pass and declare signing secrets, and check their
  availability before building. The 0.2.1 tag produced no public download assets
  because its signing credentials were unavailable to the reusable workflow.

- Official arm64 and Intel releases share a pinned certificate and stable bundle
  identifiers. The application and MCP helper are signed and verified separately.
- The permission guide explains how to recover when Accessibility is switched on
  but its saved authorization belongs to an older copy of the app.
- GitHub signing credentials are restricted to a tag-only release environment.
  PR/main checks use disposable certificates and a separate app identifier.
- Four additional signing checks verify that changed code hashes can preserve
  identity, while changed resources, another bundle ID or a missing certificate
  cannot pass the original checks. The existing 24 Swift tests and packaged MCP
  tests continue to run on both architectures.

### One-time upgrade step

When upgrading from 0.2.0 or earlier, remove the old Cliprill entry from
**System Settings → Privacy & Security → Accessibility**, add the current
`/Applications/Cliprill.app`, and enable it again. This migrates from the old
ad-hoc signature to the fixed certificate. The old switch alone may still refer
to an obsolete code identity. History and queues are preserved.

Future releases will reuse this certificate and bundle ID. The initial permission
still requires user consent; cryptographic identity checks alone do not prove
grant retention on every macOS installation.

### Downloads

- `Cliprill-0.2.2-macOS-arm64.zip`: Apple Silicon.
- `Cliprill-0.2.2-macOS-x86_64.zip`: Intel.
- `cliprill-0.2.2-source.zip`: matching source and dependency notices.
- `Cliprill-signing-certificate.pem`: public certificate for verification.
- `SHA256SUMS.txt`: checksums for the archives and certificate.

No Apple Developer Program subscription is used. These packages are self-signed,
without Developer ID signing or Apple notarization. If macOS blocks a trusted
download, use **Privacy & Security → Open Anyway**. There is no need to install
the public certificate as a trusted root or change system security settings.

See [signing and upgrades](https://github.com/LKRCharon/cliprill/blob/v0.2.2/docs/SIGNING.md)
for verification and the signing model.
